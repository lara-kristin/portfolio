Reflection

WHAT

I began the discussion assuming the value of agent-based systems came mainly from autonomy and specialisation. Anne's response changed that. She distinguished error propagation, where a flawed plan corrupts later stages, from restriction neglect, where planning silently drops a stated user constraint, and showed the second was the likelier failure. Lana then pressed a related point about fixed roles becoming a bottleneck when conditions shift.

SO WHAT

Splitting planning, retrieval and evaluation across agents can improve robustness, but the handoffs are where constraints get lost, and evaluation after retrieval cannot catch an omission it never sees. What matters is not how much autonomy an agent has but what it is exercised over. An agent that can flag a plan going nowhere shows more judgement than one that executes it faithfully, provided it cannot rewrite the user's original requirements to do so.

NOW WHAT

In future designs I would keep an explicit record of user constraints and expose the generated subquestions for approval before retrieval begins, rather than checking alignment only at the end. I would let retrieval and evaluation agents trigger replanning while returning goal-level changes to the user, with the escalation threshold set at design time rather than after a failure. My test of success would be whether the system abandons a poor plan early, not whether it completes tasks unprompted. Autonomy as an objective in itself now looks like the wrong target; autonomy over whether a plan is worth continuing looks like the right one.
