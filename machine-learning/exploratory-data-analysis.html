Exploratory Data Analysis

Exploratory analysis of the Auto MPG dataset using Python and Jupyter Notebook.

Activity Overview

This activity applied exploratory data analysis techniques to the Auto MPG dataset. The analysis examined missing values, skewness and kurtosis, correlations between numerical variables, relationships through scatter plots, and the preparation of categorical data for numerical analysis.

Analysis and Findings

Initial inspection showed 398 observations and nine variables. Although all columns initially appeared complete, the horsepower column contained six question-mark placeholders rather than numerical values. After converting horsepower to a numerical variable, these values were recognised as missing and the six affected rows were removed, leaving 392 observations.

Horsepower showed the strongest positive skewness at approximately 1.09, indicating a relatively small number of high-horsepower cars. The correlation analysis showed that fuel economy was strongly negatively associated with weight (-0.83), displacement (-0.81), cylinders (-0.78) and horsepower (-0.78). The scatter plots supported these relationships and also showed that newer cars in the dataset generally achieved higher miles per gallon.

The analysis also highlighted the importance of treating categorical variables carefully. The numerical origin codes represented categories rather than quantities, meaning correlations involving those codes were not inherently meaningful. Car names were also unsuitable for direct numerical conversion because 301 different names occurred across 392 observations. I therefore extracted vehicle brands, identified spelling variations and abbreviations, reduced 37 initial brand labels to 30 cleaned categories, and created a separate numerical brand code while retaining the original label.

Reflection

This exercise showed me that exploratory data analysis involves more than producing descriptive statistics and visualisations. A column can appear complete while still containing values that represent missing data, and numerical values do not necessarily represent quantities that should be analysed mathematically. I also saw how apparently simple categorical encoding requires prior data cleaning to avoid treating spelling variations as separate categories. These checks are important before applying machine learning methods because problems identified during EDA can directly affect how later models interpret the data.
